## Prerequisites

- A running vmem deployment
- Convex environment variables: `CLERK_SECRET_KEY`, `CLERK_PUBLISHABLE_KEY`, `CLERK_FRONTEND_API_URL`, `CONVEX_SITE_URL`, `WEB_APP_URL`
- A vmem account (sign in via Clerk)

MCP verifies the **Clerk OAuth access token**. There is no `MCP_JWT_SECRET`.

## Get Your MCP URL

```
https://<your-deployment>.convex.site/mcp
```

Team scope:

```
https://<your-deployment>.convex.site/mcp/team
```

Find your deployment slug in the Convex dashboard. The URL uses `.convex.site` (not `.convex.cloud`).

## Claude Desktop / Claude.ai

1. Open Claude Settings → Connectors (or MCP settings)
2. Add a new remote MCP connector
3. Enter your MCP URL: `https://<deployment>.convex.site/mcp`
4. Sign in with your vmem account when prompted (OAuth + PKCE)
5. The `vmem://context_prompt` resource is loaded automatically at conversation start

## Cursor

1. Open Cursor Settings → MCP
2. Add a remote MCP server
3. URL: `https://<deployment>.convex.site/mcp`
4. Complete OAuth sign-in when prompted

## OAuth Flow

vmem MCP uses standard OAuth 2.0 with PKCE:

1. MCP client discovers metadata at `/.well-known/oauth-authorization-server` and `/.well-known/oauth-protected-resource`
2. User is redirected to vmem / Clerk sign-in
3. After auth, the client receives a Clerk OAuth access token
4. The token is included in subsequent MCP requests

## Verifying Connection

Call the `ping` tool to verify connectivity:

```
→ ping
← { "ok": true, "timestamp": "2026-05-22T..." }
```

Call `whoami` to confirm your user identity and active profile:

```
→ whoami
← { "userId": "...", "activeProfile": { ... } }
```

## Interactive memory graph (`memory_graph`)

Requires an MCP Apps–capable host (Claude Desktop/Web with ext-apps support). Prompt example:

```
Show my vmem memories as an interactive graph. Use the memory_graph tool.
```

If the connector shows **Unable to reach vmem** but Cursor still works:

1. Confirm the URL ends with **`/mcp`** on **`.convex.site`** (not `.convex.cloud`).
2. **Disconnect and reconnect** the connector in Claude (re-run OAuth).
3. Ensure Convex env has `CLERK_SECRET_KEY`, `CLERK_PUBLISHABLE_KEY`, `WEB_APP_URL`, and deploy is healthy.
4. Call `ping` in Claude — if that fails, the issue is connector auth/URL, not the graph app.

## Troubleshooting

| Issue                                | Fix                                                                                       |
| ------------------------------------ | ----------------------------------------------------------------------------------------- |
| Unable to reach / Couldn't reach MCP | Use `.convex.site/mcp`; reconnect OAuth; call `ping` to verify POST works                 |
| OAuth redirect fails                 | Verify `CONVEX_SITE_URL` and `WEB_APP_URL` in Convex env                                  |
| 401 on MCP requests                  | Re-authenticate — the Clerk OAuth token may have expired                                  |
| Empty context prompt                 | First read returns a placeholder; wait for background regeneration                        |
| Wrong profile                        | Use `list_profiles` then pass `profileId` to memory tools                                 |
| Graph tool missing                   | Deploy latest backend; run `pnpm --filter @vmem/backend build:mcp-graph-ui` before deploy |
