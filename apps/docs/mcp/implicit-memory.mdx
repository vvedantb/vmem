## The Core Principle

Memory should be implicit, not explicit. The LLM should never have to "decide" to remember — relevant context should already be present when it responds.

## How It Works

```
User sends message to Claude/Cursor
  → MCP client reads vmem://context_prompt Resource
  → vmem returns synthesized user profile (markdown)
  → LLM sees it as part of system context — no tool call
  → LLM responds with full user context
```

The user and the LLM never explicitly "fetch" memories for reading. Context is just there.

## The Context Prompt Resource

### `vmem://context_prompt`

A single MCP Resource that delivers a synthesized markdown profile:

- **About me** — from user settings
- **Preferences** — from user settings
- **Pinned memories** — up to 20 verbatim pinned memory contents
- **Profile summary** — LLM-generated prose from recent activity

MIME type: `text/markdown`

### Caching Behavior

| Scenario | Behavior |
| --- | --- |
| First read (no cache) | Returns placeholder markdown, schedules background regeneration |
| Cache < 24h old | Returns cached content immediately |
| Cache > 24h old | Returns stale content, schedules refresh in background |
| Memory write | Schedules regeneration after 60s debounce |

The read is always non-blocking — MCP clients never wait on LLM generation.

## Reading vs Writing

| Operation | Mode | How |
| --- | --- | --- |
| **Reading (profile context)** | Implicit | `vmem://context_prompt` Resource |
| **Reading (query-specific)** | Explicit | `memory_retrieve` tool |
| **Searching** | Explicit | `memory_search` tool |
| **Writing (deliberate)** | Explicit | `memory_add` tool |
| **Writing (automatic)** | Background | Enrichment queue after create |

For general conversation context, reading is implicit. For query-specific retrieval (e.g. "what did we discuss about Neo4j?"), the LLM can call `memory_retrieve` explicitly.

## Why This Matters

### Competitors: Tool-Only Approach

Mem0 and Supermemory require the LLM to explicitly call `mem0.search()` or `memory.retrieve()` to get context. This has two problems:

1. **The LLM can forget to check memory** — it's an optional step that may be skipped
2. **Token overhead** — every retrieval costs a tool call round-trip

### vmem: Resource-Based Approach

vmem injects a synthesized profile via MCP Resource before the LLM starts generating. The model always has baseline user context. No tool call overhead. No "forgetting to remember."

For deeper, query-specific retrieval, `memory_retrieve` is available as an explicit tool with full context trace scoring.

## Profiles in Context

The context prompt reflects the user's active profile. Use `list_profiles` and pass `profileId` to memory tools to work with a specific profile's memories.

The `whoami` tool returns the current active profile ID.
