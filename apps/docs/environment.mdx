## Convex Backend (`packages/backend`)

Set these in the **Convex dashboard** (Settings → Environment Variables). The same names are in `packages/backend/.env.example` for local CLI tests.

| Variable                       | Required | Description                                                                                     |
| ------------------------------ | -------- | ----------------------------------------------------------------------------------------------- |
| `CLERK_FRONTEND_API_URL`       | Yes      | Clerk JWKS domain for Convex auth                                                               |
| `CLERK_SECRET_KEY`             | Yes      | Clerk secret key (MCP OAuth token verify)                                                       |
| `CLERK_PUBLISHABLE_KEY`        | Yes      | Clerk publishable key (MCP token verify)                                                        |
| `CLERK_WEBHOOK_SIGNING_SECRET` | No       | Clerk Billing webhook signing secret (`whsec_…`). Without it `POST /clerk/webhooks` answers 400 |
| `ENCRYPTION_KEY`               | Yes      | Base64-encoded AES-256 key for API key encryption                                               |
| `CONVEX_SITE_URL`              | Yes      | Your `.convex.site` URL (OAuth redirects)                                                       |
| `WEB_APP_URL`                  | Yes      | Web app origin (MCP OAuth callbacks)                                                            |
| `AI_GATEWAY_API_KEY`           | No       | Chat, embeddings, fact extraction, and Jev (`typesafe-ai/jev`) on the Convex deployment         |

V Pro is one Clerk Billing plan shared by all V apps. The Convex JWT carries no plan claim, so Convex stores plan slugs on `users.planSlugs`. A Clerk webhook keeps them current. In the Clerk dashboard (Project V, `clerk.projectv.uk`) add an endpoint at `https://clear-bear-690.eu-west-1.convex.site/clerk/webhooks`. Subscribe to `subscription.created`, `subscription.updated`, `subscription.active`, `subscription.pastDue`, `subscriptionItem.updated`, `subscriptionItem.active`, `subscriptionItem.canceled`, `subscriptionItem.ended`, `subscriptionItem.abandoned`, `subscriptionItem.incomplete` and `subscriptionItem.pastDue`. Copy the signing secret to `CLERK_WEBHOOK_SIGNING_SECRET`. For existing subscribers run `npx convex run clerkBillingBackfill:backfillUserPlanSlugs` once. Nothing gates on the plan yet.

There is **no** in-app Settings → Secrets page. Operators set `AI_GATEWAY_API_KEY` on the Convex deployment (dashboard Environment Variables or `npx convex env set`). Instruction `save` / `update` over HTTP return `422 openrouter_required` when `AI_GATEWAY_API_KEY` is missing from the deployment. The error code stays `openrouter_required` so existing clients keep matching it.

The same key turns on Jev for retrieve rerank, context pack, related memories and skill recommendations, and the [Dream Mode](/concepts/dream-mode) AI judge (Jev for near-duplicates, Qwen with thinking off for conflicts). Jev calls go through the AI Gateway only, with `disallowPromptTraining`: the gateway routes only to providers that do not train on prompts. Request-level zero data retention needs a Vercel Pro or Enterprise plan, so it is not sent; `dataPolicy: "zdr"` stays opt-in in `engine/llm/systemOneClient.ts`. Retrieve reranks automatically (no noul hard-drop). Missing key fail-opens to hybrid retrieve, and Dream Mode then runs only its deterministic steps (no 422). HTTP/SDK retrieve may pass `judge: "off"` for labelled ablation; LoCoMo CLI uses `LOCOMO_IR_JUDGE`. Live MCP retrieve does not expose that flag. Enablement notes live in `packages/backend/tests/memory/jev-retrieve-gate.md`.

Every call is logged to `openRouterLogs` and shows on the Usage page: Jev calls from retrieve, context pack, related memories and skills under **Jev**, Dream Mode calls under **Dreaming**, rollup summaries under **Rollups**.

Upgrading from the direct TypeSafe client: remove `TYPESAFE_API_KEY` from the Convex production deployment (`clear-bear-690`) with `npx convex env remove TYPESAFE_API_KEY`. It is no longer read. Keep `AI_GATEWAY_API_KEY`.

There is **no** `NEO4J_*` or `MCP_JWT_SECRET` on current `main`.

### Log retention (optional)

| Variable                        | Required | Description                                                         |
| ------------------------------- | -------- | ------------------------------------------------------------------- |
| `OPENROUTER_LOG_RETENTION_DAYS` | No       | Whole days to keep `openRouterLogs` rows. Unset keeps them forever. |

When it is set, the hourly `purge expired openRouter logs` cron deletes rows older than that many days, 500 rows a batch, and reschedules itself while more remain. It skips rows that the aggregate drain has not folded in yet. It does not touch the cost, token and model aggregates. Usage totals and the model filter therefore keep the full history, but the log list only shows rows inside the window. A blank, zero, negative or fractional value counts as unset.

There is no retention setting for `api_request` audit entries. The `convex-audit-log` component (0.2.0) only has `cleanup`, which reads the oldest rows by timestamp for every action. It can filter on `retentionCategory`, but it skips non-matching rows inside the same batch. A filtered sweep would stall behind older non-`api_request` rows, and an unfiltered sweep would also delete memory, API key and team audit history. Components keep their tables private, so the app cannot delete those rows directly.

### Nightly jobs (optional)

The `nightly maintenance` cron runs at 02:30 UTC: Dream Mode first, then rollups. See [Dream Mode](/concepts/dream-mode).

| Variable           | Required | Description                                                                                |
| ------------------ | -------- | ------------------------------------------------------------------------------------------ |
| `DREAM_DISABLED`   | No       | `1` stops nightly and manual dreaming (`dream_run` returns `disabled`). Rollups still run. |
| `NIGHTLY_DISABLED` | No       | `1` stops the whole nightly cron: dreaming and rollups. Manual dream runs still work.      |

Any other value, or unset, leaves the job on. The dream AI budget ($0.50 per UTC day, all users) and the per-user caps are constants in `engine/memory/dream/nightly.ts`, not env vars.

## Chrome Extension

Copy `apps/chrome-extension/.env.example` to `.env.local` before `pnpm ext:build`:

| Variable                     | Description                           |
| ---------------------------- | ------------------------------------- |
| `VITE_CONVEX_URL`            | Convex deployment URL                 |
| `VITE_CLERK_PUBLISHABLE_KEY` | Clerk publishable key                 |
| `VITE_CLERK_SYNC_HOST`       | Web origin used for Clerk cookie sync |

If env is omitted, the extension falls back to constants in `apps/chrome-extension/src/lib/constants.ts`. These point to Project V Clerk (`clerk.projectv.uk`), prod Convex (`clear-bear-690`), and `https://vmem.projectv.uk`.

## SDK / HTTP scripts

Root `.env.example` / `packages/sdk/.env.example`:

```
VMEM_API_KEY=vmem_sk_...
VMEM_BASE_URL=https://your-deployment.convex.site
```

## Generating ENCRYPTION_KEY

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

Copy the output into your Convex environment variables.

## Local-only evals

The end-to-end memory on/off A/B eval (`eval:e2e-ab`) runs on a developer machine only. It is not part of CI. It reads `EVAL_E2E_AB`, `VMEM_API_KEY` and `CONVEX_SITE_URL` from your shell. It sets nothing on the Convex deployment.
