## Access Model

vmem exposes two programmatic surfaces:

1. **Convex SDK** (first-party) — `authAction`s with Clerk authentication
2. **HTTP API** (API keys) — `/api/v1/memories*` on `https://<deployment>.convex.site` with `Authorization: Bearer vmem_sk_...`

### Convex SDK (Clerk)

```typescript
import { ConvexHttpClient } from "convex/browser";
import { api } from "@vmem/backend/convex/_generated/api";

const client = new ConvexHttpClient(process.env.VITE_CONVEX_URL);
// Authenticate with Clerk token before calling actions
const memories = await client.action(api.memoryApi.listMemories, {
  limit: 20,
  offset: 0,
});
```

First-party clients (web, Chrome extension) use `useAction(api.memoryApi.*)` with live Clerk sessions.

### HTTP API (API keys)

Store, retrieve, update, and delete memories without the Convex SDK. See [HTTP Memories API](/api-reference/http-memories).

For third-party integrations, use the [`@vmem/sdk`](/sdk/quickstart) package:

```typescript
import { VMemory } from "@vmem/sdk";

const vmem = new VMemory({
  apiKey: "vmem_sk_...",
  baseUrl: "https://<deployment>.convex.site",
});
await vmem.save("User prefers TypeScript");
const result = await vmem.search("What language does the user prefer?");
```

## Authentication

All public Convex functions require a signed-in Clerk user. Protected functions use `authAction`, `authMutation`, or `authQuery` builders that verify identity and inject `ctx.userId`.

There is no `userId` parameter — identity is resolved from the Clerk session automatically.

## MCP HTTP Endpoint

MCP is a separate HTTP surface (Clerk OAuth, not API keys):

```
POST https://<your-deployment>.convex.site/mcp
```

See [MCP Setup](/mcp/setup).

## Health Check

```
GET https://<your-deployment>.convex.site/health
```

Returns `{ "status": "ok" }`.

## Common Patterns

### Pagination

List endpoints accept `limit` and `offset` parameters.

### Memory Types

- `profile` — stable user facts and preferences
- `episodic` — session-specific or temporal events
- `knowledge` — learned information and skills

### Memory Status

- `active` — normal state
- `pinned` — protected from expiry, boosted in ranking
- `suppressed` — hidden from retrieval but not deleted
- `expired` — past its expiry date

### Error Handling

Convex actions throw standard JavaScript errors with descriptive messages. Unauthenticated calls fail with an auth error. HTTP errors use `{ "error": "..." }` — see [HTTP Memories](/api-reference/http-memories#errors).

## TypeScript Types

Import return types from generated Convex API:

```typescript
import type { FunctionReturnType } from "convex/server";
import { api } from "@vmem/backend/convex/_generated/api";

type Memory = FunctionReturnType<typeof api.memoryApi.getMemory>;
type RetrieveResult = FunctionReturnType<typeof api.memoryApi.retrieveMemories>;
```

Shared memory wire types also ship from `@vmem/sdk`.
