The synthesized profile is **not** a public Convex `authAction`. MCP serves it as the `vmem://context_prompt` resource and the `context_prompt_get` tool, both backed by the internal action `contextPromptApi.mcpGetContextPrompt`.

## Get Context Prompt (MCP)

Personal MCP connector:

- Resource: `vmem://context_prompt`
- Tool: `context_prompt_get`

**Returns:**

```typescript
{
  content: string; // markdown profile
  generatedAt: number; // timestamp (0 if placeholder)
  isPlaceholder: boolean; // true on first call before regeneration
}
```

## Content Model

The context prompt is built from:

1. **User settings** — `aboutMe` and `preferences`
2. **Pinned memories** — up to 20 verbatim pinned memory contents
3. **Profile summary** — LLM-generated prose from recent memories (when OpenRouter is configured)
4. **Available skills** — enabled skills index (name + description)

## Caching

- First call with no cache returns a placeholder and schedules background regeneration
- Cache older than 24 hours triggers a refresh (returns stale content immediately)
- Memory writes schedule regeneration with a 60-second debounce

See [Implicit Memory](/mcp/implicit-memory).
