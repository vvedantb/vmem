---
title: "Proposed Updates"
description: "Review and resolve conflicting memory updates"
---

Convex `authAction`s in `proposedUpdateApi`. Pending rows live in the `proposedUpdates` table. Dream Mode writes `merge`, `update` and `contradiction` proposals (see [Dream Mode](/concepts/dream-mode)); instruction update applies supersedes immediately so retrieve is not blocked on proposal review.

## List Proposed Updates

```typescript
await client.action(api.proposedUpdateApi.listProposedUpdates, {
  profileId: "optional-profile-id",
});
```

**Returns:** `ProposedUpdateNode[]` (pending proposals for the caller / profile)

## Resolve Proposal

<ParamField body="proposalId" type="string" required>
  The proposal ID
</ParamField>
<ParamField body="action" type="string" required>
  `"approve"` or `"reject"`
</ParamField>
<ParamField body="winnerMemoryId" type="string" />
<ParamField body="selectedSourceMemoryIds" type="string[]">
  Merge proposals only: the sources to merge (default all)
</ParamField>
<ParamField body="profileId" type="string" />

```typescript
await client.action(api.proposedUpdateApi.resolveProposal, {
  proposalId: "proposal_abc",
  action: "approve",
});
```

**Returns:** `{ status, materializedMemoryId? } | null`
