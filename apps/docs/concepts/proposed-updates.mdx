## The Problem

Imagine a user tells an AI assistant: "I prefer Python." A week later, they say: "Actually, I've switched to TypeScript." What should the memory system do?

Most systems silently overwrite. The old memory is gone — no record of what changed or why.

## How vmem Handles Conflicts

When vmem detects that new information conflicts with an existing memory, it creates a **proposed update** instead of overwriting. The original memory remains unchanged until you explicitly approve the change.

```
New memory extracted: "User prefers TypeScript"
  → vmem detects conflict with: "User prefers Python"
  → Creates a proposed update (pending)
  → User reviews and approves/rejects via Inbox or API
```

## Proposal Kinds

| Kind | Description |
| --- | --- |
| `update` | Replace memory content with proposed content on approve |
| `delete` | Delete the target memory on approve |
| `insight` | Synthesize a new memory from connected sources (Dream Mode) |
| `connection` | Link related memories with a new relationship |
| `contradiction` | Flag conflicting information for review |
| `anomaly` | Surface unusual patterns in memory data |

Legacy kinds (`update`, `delete`) come from fact extraction. Synthesis kinds (`insight`, `connection`, `contradiction`, `anomaly`) are produced by Dream Mode V2.

## Why This Matters

- **No silent data loss** — the original memory is preserved until you decide
- **Audit trail** — every proposal records what was proposed, when, and what happened
- **User control** — you decide what your AI remembers, not the system

## Proposed Update Lifecycle

```
pending → approved (memory updated or materialized)
        → rejected (original preserved)
```

## Managing Proposals

### Via Dashboard

Go to **Inbox → Proposals** (`/inbox/proposals`). Each card shows the target memory title, proposed change, and reason, with approve/reject buttons.

### Via API

```typescript
// List pending proposals
const proposals = await convex.action(api.proposedUpdateApi.listProposedUpdates, {});

// Approve or reject
await convex.action(api.proposedUpdateApi.resolveProposal, {
  proposalId: "proposal_abc",
  action: "approve", // or "reject"
});
```

See [Proposed Updates API](/api-reference/proposed-updates) for response shapes.
