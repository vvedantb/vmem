## What are Profiles?

Profiles are containers that organize **where memories get saved**. Each user has one or more personal profiles, and team members share a team profile for company knowledge.

## Personal Profiles

Every user gets a default profile on first sign-in. You can create additional profiles from **Settings → Profiles** (`/settings/profiles`).

Use cases:
- Separate work and personal memories
- Different projects with distinct context
- Testing vs production memory sets

When creating a memory, the active profile determines where it is stored. Switch profiles in the save form or profile dropdown without changing routes.

## Team Profiles

Each team has exactly one profile. All team members can read and write memories on that profile. Original creator attribution is preserved on each memory.

See [Teams](/features/teams) for the full team workflow.

## Profile in Retrieval

- **MCP tools** default to the active profile unless `profileId` is specified
- **Dashboard stats** show user-wide totals (not filtered by profile)
- **List and graph views** can filter by profile via URL params

## MCP Integration

Use `list_profiles` to see available profiles, then pass `profileId` to `memory_add`, `memory_search`, or `memory_retrieve` to target a specific profile.

The `whoami` tool returns the authenticated user ID and active profile.
