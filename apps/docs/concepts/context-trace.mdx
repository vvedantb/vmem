## What is Context Trace?

When you retrieve memories from vmem, every result comes with a **context trace** — a breakdown of exactly why that memory was returned and how it scored.

No black boxes. No mystery rankings.

## Why It Matters

Most memory systems return results ranked by a single similarity score. You have no way to know:

- Was this memory returned because it's recent or because it's semantically relevant?
- Is a pinned memory being boosted over something more contextually appropriate?
- Why was one memory ranked higher than another?

Context trace answers all of these questions.

## How Retrieval Works

When you call `memoryApi.retrieveMemories`, vmem scores each candidate memory across multiple signals:

1. **Fulltext** — Keyword match against memory title and content
2. **Vector** — Embedding similarity to the query
3. **Chunk** — Paragraph-level match within long memories
4. **Entity** — Named entity overlap between query and memory
5. **RRF** — Reciprocal rank fusion combining the above signals
6. **Recency** — How recently the memory was created or updated
7. **Confidence** — The memory's stored confidence score
8. **Graph path** (optional) — Multi-hop traversal through related memories
9. **Reranker** (optional) — Cross-encoder reranking score

Each signal contributes to a final composite score, and the trace shows the contribution of each.

## Response Shape

Each retrieved memory includes a `trace` object:

```json
{
  "id": "mem_abc123",
  "title": "Preferred stack",
  "content": "User prefers Next.js with Convex backend",
  "trace": {
    "score": 0.87,
    "reason": "Strong vector match + recent update",
    "scoreBreakdown": {
      "fulltext": 0.3,
      "vector": 0.85,
      "chunk": 0.0,
      "entity": 0.1,
      "rrf": 0.72,
      "recency": 0.9,
      "confidence": 0.95
    }
  },
  "matchedChunk": {
    "content": "User prefers Next.js with Convex backend",
    "position": 0
  }
}
```

When retrieval matches a specific paragraph inside a long memory, `matchedChunk` shows which passage triggered the match.

## Use Cases

- **Debugging retrieval** — understand why the wrong memory surfaced
- **Tuning** — adjust scoring weights based on trace analysis
- **Transparency** — show end users why certain context was used
- **Audit** — maintain a record of what informed each LLM response

Chat and voice surfaces memory title badges under assistant messages, with traces persisted in `chatMessageMemoryRefs` for reload.
