## What is vmem?

vmem is a persistent memory layer that lets any AI model store, retrieve, and update user knowledge across sessions and platforms. Instead of each LLM maintaining its own siloed memory, vmem provides a single source of truth that any model can connect to via REST API or MCP.

## The Problem

LLMs lack persistent long-term memory. Users repeatedly provide the same information, rebuild context each session, and lose personalisation when switching between models. Existing solutions like Mem0 and Supermemory are proprietary and tied to specific ecosystems.

## How vmem is Different

### Context Trace
Every memory retrieval explains **why** it matched — with a full score breakdown across recency, relevance, and metadata signals. No black-box retrieval.

### Proposed Updates
When new information conflicts with existing memories, vmem doesn't silently overwrite. It creates a **proposed update** that you can approve or reject, preserving an audit trail.

### Implicit Memory via MCP
Competitors require the LLM to explicitly call tools to fetch memories. vmem injects relevant context **before** the LLM responds using MCP Resources — the model never has to "decide" to remember.

### Memory Lifecycle
Memories can be pinned, suppressed, expired, or audited. Full lifecycle management with event trails.

## Architecture

| Component | Role |
| --- | --- |
| **Hono API** | REST memory engine — CRUD, search, retrieval |
| **Neo4j** | Memory graph — nodes, edges, traversal |
| **Convex** | Users, preferences, API keys, auth |
| **MCP Server** | Implicit memory via Resources, explicit writes via Tools |
| **Next.js** | Web dashboard for browsing and managing memories |
