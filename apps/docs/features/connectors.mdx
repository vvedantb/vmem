## Overview

Connectors integrate external data sources with vmem. Connect services from **Sources → Connectors** (`/{workspace}/sources/connectors`). `/settings/connectors` redirects there.

## Available Connectors

| Connector    | Status    | Auth  | What syncs                                                         |
| ------------ | --------- | ----- | ------------------------------------------------------------------ |
| Google Drive | Available | OAuth | Google Docs, Sheets, and Slides                                    |
| Notion       | Available | OAuth | Pages shared with the integration                                  |
| Gmail        | Available | OAuth | Mail from the last 90 days, up to 300 messages per sync            |
| Figma        | Available | OAuth | Files in configured teams (up to 50), with page names and comments |
| GitHub       | Available | OAuth | Issues and pull requests updated in the last 90 days, up to 300    |

OneDrive, Linear, Dropbox, and Slack connectors are **not** wired on current `main`. GitHub codebase sync is [removed](/features/codebases). The GitHub connector syncs issues and pull requests only.

Each synced item becomes one memory. The memory `source` matches the connector (`google_drive`, `notion`, `gmail`, `figma`, `github`). Each item has a stable source ID, so a re-sync updates the memory in place rather than adding a duplicate:

| Connector | Source ID                       | Link                                           |
| --------- | ------------------------------- | ---------------------------------------------- |
| Gmail     | Gmail message ID                | `https://mail.google.com/mail/u/0/#inbox/{id}` |
| Figma     | File key                        | `https://www.figma.com/file/{key}`             |
| GitHub    | Issue or pull request `node_id` | The issue or pull request `html_url`           |

Connected connectors sync once a day. If one item fails (for example, a rate-limited Figma file), the sync logs it and continues with the rest.

## OAuth Setup

| Connector    | Variables                                                  |
| ------------ | ---------------------------------------------------------- |
| Google Drive | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`                 |
| Gmail        | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`                 |
| Notion       | `NOTION_CLIENT_ID`, `NOTION_CLIENT_SECRET`                 |
| Figma        | `FIGMA_CLIENT_ID`, `FIGMA_CLIENT_SECRET`, `FIGMA_TEAM_IDS` |
| GitHub       | `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`                 |

Also required: `CONVEX_SITE_URL` for OAuth callback redirects. Every provider uses the same callback URL:

```
https://<CONVEX_SITE_URL>/api/auth/connector/callback
```

Set the variables with `npx convex env set` or in the Convex dashboard.

### Google (Drive and Gmail)

Drive and Gmail share one Google Cloud OAuth client but are separate grants. Each connector asks only for its own scope and stores its own tokens.

1. In Google Cloud Console, enable the **Google Drive API** and the **Gmail API** for the project.
2. On the OAuth consent screen, add the scopes `https://www.googleapis.com/auth/drive.readonly` and `https://www.googleapis.com/auth/gmail.readonly`. `gmail.readonly` is a restricted scope. Google requires app verification before external users outside your test user list can connect.
3. On the OAuth client (type **Web application**), add the callback URL above as an authorised redirect URI.

Both connectors request offline access, so tokens refresh automatically. Disconnecting revokes the Google token (best effort).

### Figma

1. Create an OAuth app in the Figma developer settings.
2. Add the callback URL above as a redirect URL.
3. Grant the scopes `current_user:read`, `file_content:read`, `file_comments:read`, and `folders:read`.
4. Set `FIGMA_CLIENT_ID` and `FIGMA_CLIENT_SECRET`.
5. Set `FIGMA_TEAM_IDS` to a comma-separated list of team IDs.

The Figma API cannot list a user's teams, so the connector reads team IDs from `FIGMA_TEAM_IDS`. To find a team ID, open the team page in Figma. The ID is the number after `/team/` in the URL. The setting applies to the whole deployment. Teams that a user cannot access are skipped. If the variable is empty, the sync completes with no files.

Figma access tokens expire and refresh automatically. Figma has no token revoke endpoint, so disconnecting deletes the stored tokens only.

### GitHub

1. Create an **OAuth App** under GitHub → Settings → Developer settings.
2. Set the authorisation callback URL to the callback URL above.
3. Set `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET`.

The connector requests `read:user` and `repo`. GitHub has no read-only scope for private repository issues, so `repo` is the narrowest classic OAuth scope that lists issues and pull requests in private repositories. vmem only reads data. OAuth App tokens do not expire. Disconnecting revokes the app grant (best effort).

## How Connectors Work

1. User initiates OAuth from Sources → Connectors
2. Convex handles the OAuth flow
3. Tokens are encrypted at rest (AES-GCM, same as API keys)
4. Sync jobs pull data from the connected service
5. Imported content can become memories
