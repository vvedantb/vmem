## Overview

API keys provide programmatic access to vmem. Create and manage keys from **Settings → API → Keys** (`/settings/api/keys`).

## Key Format

Keys are prefixed with `vmem_sk_` followed by a base64url-derived suffix:

```
vmem_sk_a1b2c3d4e5f6...
```

## Creating a Key

1. Go to **Settings → API → Keys**
2. Click **Create key**
3. Enter a name (max 50 characters)
4. Copy the full key — you can also reveal it later from the keys table
5. The dashboard shows a masked version by default

## Storage

Keys are hashed for lookup and AES-GCM encrypted at rest (`v1:` format). Requires `ENCRYPTION_KEY` in Convex environment variables.

## Dashboard Operations

| Function | Description |
| --- | --- |
| `apiKeys.createMy` | Create a new key (returns plaintext once) |
| `apiKeys.listMy` | List keys (masked) |
| `apiKeys.revokeMy` | Revoke an active key (status → revoked) |
| `apiKeys.deleteMy` | Permanently delete a key (active or revoked) |
| `apiKeys.revealMy` | Decrypt and reveal a key |

## HTTP API

Use API keys as Bearer tokens against the Convex HTTP deployment:

```
Authorization: Bearer vmem_sk_...
```

Base URL: `https://<your-deployment>.convex.site`

| Endpoint | Method | Description |
| --- | --- | --- |
| `/api/v1/memories` | `POST` | Store (create) a memory |
| `/api/v1/memories/retrieve` | `POST` | Semantic retrieve |
| `/api/v1/memories` | `PATCH` | Update a memory |

Example:

```bash
curl -X POST "https://<deployment>.convex.site/api/v1/memories" \
  -H "Authorization: Bearer vmem_sk_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"title":"Note","content":"Hello","type":"knowledge","source":"api","tags":[],"confidence":1}'
```

Full request/response reference: [HTTP Memories API](/api-reference/http-memories).

## Other Clients

First-party apps (web, extension, mobile) use Clerk via the Convex SDK. MCP clients use OAuth + Bearer JWT at `/mcp`, not API keys.

Each HTTP request increments the key's `requestCount` and updates `lastUsedAt`.
