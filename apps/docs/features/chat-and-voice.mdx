## Overview

vmem includes built-in chat and voice interfaces on `/chat` and `/voice`.

**Local mode** (default) runs models in your browser via WebLLM. **Cloud mode** streams free OpenRouter models through Convex with the same personal MCP tool surface (memories, skills, wiki, codebases).

## Chat modes

| Mode | Where it runs | Memory access | Requirements |
|------|---------------|---------------|--------------|
| **Local** | Browser (WebLLM) | Pre-turn RAG via `memoryApi.retrieveMemories` | Model loaded in Settings → Models |
| **Cloud** | OpenRouter via Convex | Tool calling (`memory_search`, `memory_add`, …) | `OPENROUTER_API_KEY` in Settings → Secrets; free model selected in chat footer |

Toggle **Local / Cloud** in the chat footer. Cloud only lists models that are free (`pricing = 0`) and support tool calling.

## Local chat — memory retrieval

1. User sends a message
2. Client calls `memoryApi.retrieveMemories` with the message text (limit: 8)
3. Convex returns ranked memories with context traces + user settings context
4. `buildLocalChatSystemPrompt` formats memories into the system prompt
5. Local LLM streams a response with full memory context
6. Memory title badges appear under the assistant message
7. References are persisted in `chatMessageMemoryRefs` for reload/history

Local chat uses `VMEM_LOCAL_CHAT_CORE` as the base system prompt. Voice uses `VMEM_VOICE_CORE` with the same retrieval pipeline.

## Cloud chat — vmem tools

1. User sends a message; Convex saves the prompt and schedules `streamAsync`
2. OpenRouter model streams with personal MCP tools (same handlers as the MCP server)
3. The model can call `memory_search`, `memory_retrieve`, `memory_add`, skills, wiki, and codebase tools in a loop (max 10 steps)
4. Tool call steps appear in the message UI; memory badges are written when memory tools return ids
5. Usage is attributed under OpenRouter logs feature `chat`

Cloud chat uses `VMEM_CLOUD_CHAT_CORE` plus an MCP-style skills index (`buildCloudChatSystemPrompt`). There is no automatic pre-RAG — the model uses tools to fetch memories when needed.

**Note:** Free model availability on OpenRouter changes frequently. The model list is fetched from the OpenRouter catalog (cached ~6h) with a hardcoded fallback if the fetch fails.

## Local models

Models are downloaded and run via WebLLM in the browser. Configure available models in **Settings → Models** (`/settings/models`).

## Memory badges

Assistant messages show badges linking to the memories that informed the response. Click a badge to open the memory detail view. Cloud mode populates badges from tool results (`memory_search`, `memory_retrieve`, `memory_add`).

## Mobile

The Expo mobile app (`apps/mobile`) includes local chat + retrieval only. Cloud chat parity is web-only for now. See [Mobile](/features/mobile).

## OpenRouter key

- **Local chat/voice:** No OpenRouter key required for inference (embeddings for retrieval may still use OpenRouter on the backend when configured).
- **Cloud chat:** Requires per-user `OPENROUTER_API_KEY` in Settings → Secrets.
