# vmem — project structure

Monorepo: Next.js web app (`apps/web`), Expo mobile (`apps/mobile`), Convex backend (`packages/backend`) with inline MCP at `*.convex.site/mcp`, shared UI (`packages/ui`).

**Chat + memories:** Local WebLLM chat (`/chat`, `useLocalChat`) and voice (`/voice`) call Convex `memoryApi.retrieveMemories` before each turn to inject Neo4j-ranked memories into the system prompt. Assistant message keys `${threadId}-${order}-${stepOrder}` align persisted memory reference badges via `chatMessageMemoryRefs` and `getThreadMessageMemoryRefs`. Shared prompt helpers live in `packages/backend/src/memoryRagPrompt.ts` (export `@vmem/backend/memoryRagPrompt`). Memory enrichment (semantic tags + related-memory links) runs only on the client: `listRecentMemoryTitlesForEnrichment` + local LLM + `applyEnrichment`; shared prompt/parse in `packages/backend/src/enrichmentPrompt.ts` (`@vmem/backend/enrichmentPrompt`).

**Deferred local enrichment queue:** Convex table `pendingMemoryEnrichment` stores `memoryId` + `source` (`mcp` | `import` | `web`) per user when MCP/import/web create memories without inline local enrichment. `pendingEnrichment` exposes enqueue/list/remove. Web: `MemoryContext` enqueues on web create when the local model is not ready; `useEnrichmentQueueDrain` (mounted via `PendingEnrichmentRunner` in `ClientProvider`) drains up to 50 items when WebLLM is ready; sidebar footer shows a pending count above stats; sonner toasts on batch start/complete. Chrome extension: `pending-enrichment-drain.ts` runs after enrichment init / successful WebLLM load, same pipeline + cap.

**Import:** Settings → Import (`/settings/import`) parses ChatGPT or Claude official exports (ZIP/JSON) client-side and creates Neo4j memories via `memoryApi.createMemory` with `queueForLocalEnrichment: true` (episodic, tagged `import` + provider); no chat thread replay.
